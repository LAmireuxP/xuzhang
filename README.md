# 序章

HyperOS 的开机第一屏（bootloader logo）管理器，KernelSU / SukiSU / APatch / Magisk 都能用。中文界面，换第一屏、导入、删除、拖拽排序；关掉模块或者卸载之后，会自动回到原厂 logo。

> 界面需要管理器的 `window.ksu` 桥，也就是 KernelSU / SukiSU / APatch / FolkPatch（或支持该桥的管理器，如 MMRL）。**Magisk 没有这个界面**，那边只能用命令行 `bin/ctl.sh`。

开机第一屏是**开机时最先看到的那张图**——在开机动画之前，由 bootloader 直接读 `logo` 分区显示。它和「开机动画」（`bootanimation.zip`）是两回事，前者更靠前，且**运行时拦不住**（bootloader 在 Android 起来之前就读完了），所以这个模块的做法是直接改 `logo` 分区。

## 能干什么

- 换第一屏：界面里点「替换」，**重启就能看到**（第一屏每次开机都显示，不用等什么）
- 导入自己的：把符合格式的 bmp 丢进「下载」目录点「扫描目录」，或者点「选择文件」自己翻
- 调顺序：按住每行左边的 ⠿ 上下拖，或者用 ▲▼ 一格一格移，松手就存
- 恢复原厂：工具栏上的「恢复原厂」，用安装时备份的那份镜像把分区还原
- 界面跟随系统深浅色，也可以手动固定成浅色或深色

## 安装

管理器里刷 `release/xuzhang-1.0.0.zip`，重启，再打开模块的「设置」进界面。里面自带一张示例第一屏，装完就能用；「原厂第一屏」不占列表条目，工具栏上的「恢复原厂」就是它。

安装时做三件事：把内置的图入库、**把整个 logo 分区备份下来**（存的是当前分区内容——如果之前用别的工具改过第一屏，这份备份也是改过的）、在 `/data/adb/post-fs-data.d/` 和 `/data/adb/service.d/` 各放一个 `xuzhang-guard.sh`。守卫脚本在模块外面，作用只有一个：模块被关掉或删掉之后，把它**曾经改过的那些槽位**按备份还原回原厂（没动过的槽位不碰）。卸载时会先还原，还原成功了才删守卫——万一失败，守卫留着重试。

## 会替换哪几张图（这个不用你操心）

logo 分区里不是一张图，而是**一叠图**，开机时按状态挑一张显示。比如 K30S 这台分区里有 8 张：正常开机 logo、`FASTBOOT`、**带解锁标记的 logo**、系统损坏警告、几张 `Redmi + android`。

所以「换第一屏」实际要换的是其中**属于开机 logo 的那几张**（解锁 BL 后显示的那张会多个小标记，是另一张图）。这件事模块**自己判断，界面上不出现这个概念**：

- 判据：第 1 张（正常开机 logo）+ 所有「和它几乎是同一张图」的槽位
- 用逐字节差异判定，阈值 1.55%（K30S 实测：带解锁标记那张差 1.298%，最近的诊断屏差 1.805%）
- 这么定**是安全的**：只会命中「跟开机图几乎一模一样的图」，不会误伤 `FASTBOOT`、系统损坏提示这类完全不同的屏
- 安装时算一次并记下来。要手动指定：`bin/ctl.sh slots set 1 3`；要重算：`bin/ctl.sh slots auto`

> 阈值是启发式的。换完如果第一屏没变化，多半是没算对——把 `bin/ctl.sh slots` 的输出发出来看看，或者手动 `slots set`。

## 用法

1. 进界面，点某张的「替换」，重启
2. 加自己的图：必须是 **BMP**，而且**宽高、色深要和本机槽位里的原图完全一致**（这样字节长度才一致，才能原地覆盖）。不符合界面会告诉你本机需要什么尺寸
3. 图都放在 `/data/adb/bootlogos/`，当前选的是哪张记在 `var/state/selected.txt`，备份和守卫信息在 `/data/adb/bootlogo-safety/`（整分区镜像 + `guard.info`）**别删**，素材库 `/data/adb/bootlogos/` 可以随便删

## 怎么做出能用的图

手机上没有图像处理工具（toybox/busybox 都没有），所以缩放、居中、转格式这一步在电脑上做：

```
pip install pillow
python tools/logo_convert.py 我的图.png 输出.bmp --size 1080x2400
```

它会等比缩放、居中贴到黑底、补成目标分辨率再存成 24bpp BMP。本机需要什么尺寸，在模块界面点「槽位」那张卡片就能看到（比如 K30S 是 `1080x2400 24bpp`、7776054 字节）。

`--scale 0.8` 可以再留一圈黑边；`--probe 某张.bmp` 只校验一张现成 BMP 合不合规。

## 安全设计

直接写分区是有风险的操作，所以这个模块的每一步都以「别把分区写坏」为前提：

- **动分区前必须先有完整备份**（安装时就做了），备份失败就拒绝写入，界面会提示
- **用过之后缺备份不补造**：备份被删掉、而模块此前已经改过分区时，此刻的分区内容很可能不是原厂——这时它拒绝写入，而不是伪造一份假的「原厂备份」（这个坑真踩过一次：自动补的备份把改过的样子当成了原厂）
- **只改你勾选的那几个槽位**，分区其余部分一个字节都不碰
- **替换图先全量校验**（宽高、色深、字节长度都对得上）才动分区，任一槽位对不上就整体不写
- **槽位位置不写死**：从分区头部的 `LOGO!!!!` 魔数推起，每个槽位再用 BMP 头逐项校验，校验不过就停，不会盲写
- 写完之后**回读校验**：把**每个目标槽位**的内容读回来算 md5，和写入记录比对，对不上状态里会显示 `applied=no`
- `service.sh` 每次开机会对一次账：ROM 更新之类的把分区刷回原厂了，它会把你要的那张补写回去（选了「恢复原厂」时不做事，避免每次开机白写一遍）
- 关掉模块/卸载 → 守卫脚本把它改过的槽位还原回原厂；卸载时**先还原、成功才拆守卫**

## 测过的机器

**能用**：Redmi K30S 至尊纪念版（apollo，HyperOS 4.0 / Android 17，1080×2400，APatch + FolkPatch）。

**用不了**：Redmi K60 Pro（socrates，1440×3200，SukiSU）。这台**没有 `logo` 分区**，而且穷尽搜索都找不到可替换的第一屏数据：

- `splash` 分区（32.6MB）**100% 全零**；`bk01`~`bk51`、`gsort`、`devinfo`、`dip`、`frp` 这一批可疑小分区**也全是零**
- 全分区扫 `LOGO!!!!` 容器魔数 → 无；扫合法 BMP 头 / PNG / JPEG / 「黑底白字」位图特征（还把 190MB 里的 LZMA、gzip 流解开再扫）→ **无**
- 系统自带动画（`/system/media/bootanimation.zip`）画的是「Powered by Xiaomi HyperOS」，不是品牌 logo

但开机确实能看到白色 Redmi logo，所以它只能是 **bootloader（abl/xbl）里以某种编码资源的形式**画出来的 —— 这是推断：我能证明的是「没有任何分区含有我能识别的图片数据」。要改它就得改并刷写 bootloader，那是启动链上的东西、写坏会不开机，**不属于本模块的范围**。

在这类机器上模块会**层层拒绝**（绝不瞎写）：`status` 里 `part=` 为空、`backup` 报失败、`slots auto` 报失败，没有备份就绝不会动分区。

其它机器没试过。这个模块靠「魔数 + BMP 头」自动识别 logo 分区里的槽位，**识别不出来就拒绝写入**（界面会报错），不会瞎写。判断你这台行不行：装完在界面里看「当前第一屏」那行——如果meta里报不出分区大小，就是认不出来。命令行版：`bin/ctl.sh status`，看 `part=` 后面有没有内容。

## 免责

就上面那台机器测过，别的都没测。**这是直接写分区的操作，比换开机动画风险高**，自己判断要不要用；出了问题是自己的事（开不了机、第一屏不对之类），我不担责任。刷之前先备份，确认自己有救砖的办法。

好消息是 `logo` 不是启动关键分区：就算写坏了，通常也只是第一屏不显示或花屏，不影响进系统；实在不行可以用 fastboot 单独刷回 logo 分区，或者用本模块「恢复原厂」（备份是整分区镜像）。

## 其他

技术细节，给要改代码的人：

- logo 分区结构（实测）：偏移 `0x4000` 起是头部，魔数 `LOGO!!!!`；其后第 1 个 u32 是「首槽位偏移 / 4096」，第 2 个 u32 是「块大小 / 4096」。槽位连续排列，每槽位一张 BMP
- 每张图是 24bpp BMP，1080×2400 对应 7776054 字节；槽位块大小 1899×4096 = 7778304 字节，尾部是补位
- 原地覆盖用 `dd bs=4096 seek=<槽位偏移/4096> conv=notrunc`，只写 BMP 本身的字节数，块尾补位不动
- 目标槽位记在 `var/state/slots.txt`；守卫要用的信息单独写在模块外的 `/data/adb/bootlogo-safety/guard.info`，这样模块目录被删掉后守卫仍然能还原。守卫写之前会先比一下分区尺寸和备份是否一致（ROM 更新换了几何就不写——宁可不还原，也不按旧偏移写坏分区）
- `bin/ctl.sh` 的命令：`list / status / info / slots [set N...] / select N / import PATH / delete N / scan / ls DIR / reset / order NAME... / backup / restore / guard / unguard / deploy / bootcheck`
